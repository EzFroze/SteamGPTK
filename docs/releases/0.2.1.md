# SteamGPTK 0.2.1

Fix game-session watchers that could remain active after a game had closed. The previous detector matched `.exe` and renderer paths ending in `/wine` anywhere in a command line, so launcher scripts could mistake one another for a running game. Several stale watchers could accumulate and consume CPU across launches.

The detector now identifies native Wine loader processes, recognizes Windows executable paths, and excludes Wine helpers by their executable name. Session waiting and game-window activation use the same selection. Regression checks cover detection, activation and completion after the real game exits.

Half-Life 2 testing on an M1 Pro showed a substantial reduction in visible freezes after stale watchers were removed. This addresses launcher overhead; it does not establish performance for other games or all 32-bit applications.

## Update

1. Quit games, Wine tools and Steam.
2. Replace the previous SteamGPTK app with this version.
3. Run **Install / Repair**, then start Steam again. Updating only the standalone `run` script is insufficient because the Steam module recreates it at startup.

Existing Wine/GPTK files, game prefixes and saves are retained by the upgrade. Users upgrading from 0.1.x also receive the 0.2.0 naming migration and automatic D9VK support.

The app is ad-hoc signed and is not notarized. Apple GPTK/D3DMetal and Wine runtime binaries are not bundled; users import their own GPTK DMG.
